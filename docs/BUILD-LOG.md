# 만든 과정 기록 (BUILD-LOG)

영어 어근 단어 암기 웹 게임 "어근 디펜스"를 처음부터 배포까지 만든 과정입니다.
코딩을 잘 몰라도 다시 따라 할 수 있게 쉬운 말로 적었습니다.

## 1. 단계별 진행 순서

1. **계획 세우기**: 붙여 둔 아이디어(디펜스, 육성, 모험, 미니게임, 경쟁)가 너무 커서, 첫 버전은 **디펜스 + 육성**만 만들기로 정했습니다. 나머지는 나중으로 미뤘습니다.
2. **큰 결정 4가지**: 웹앱으로 만들기 / 기록은 기기 안에만 저장 / 단어는 AI가 만들고 사람이 검수 / 배포는 GitHub.
3. **첫 버전 만들기**: 어근 29개, 단어 118개로 학습 카드, 전투(10문제), 레벨·코인·연속 학습, 성장 기록을 만들었습니다.
4. **직접 실행해 보기**: `index.html`을 더블클릭해서 브라우저에서 확인했습니다.
5. **기능 추가**: 음성(단어·예문 읽어 주기), 전투 중간에 그만두기, 어근당 단어 5~10개로 늘리기.
6. **단어 대량 추가**: 어근 101개, 단어 635개까지 늘렸습니다. (이후 기존 어근 보충과 새 어근 28개 추가로 어근 129개, 단어 1,198개. 지금 숫자는 아래 14·15번 참고)

9. **GitHub에 올리기**: 저장소 `root-word-game`을 공개로 만들고 `git push`, 그다음 Pages를 켰습니다.

12. **미니게임 4종 추가** (2026-11-15): 홈에 "🎮 미니게임" 메뉴를 만들고 아래 4개를 넣었습니다. 전투 기록(오답 수)은 건드리지 않고 코인만 주며, 최고 기록은 성장 기록에 표시됩니다.

13. **미니게임·전투 고치기** (2026-11-15, 커밋 `55e0734`): 직접 해 보고 불편하거나 이상한 점을 고쳤습니다.
    - **설명이 너무 짧음**: ○× 퀴즈와 어근 분류 달리기에서 정답·오답 뒤에 뜻만 나왔습니다. 전투처럼 뜻·어근·예문·한글 번역이 모두 나오게 했습니다.
    - **자동으로 넘어감**: 설명을 읽기 전에 다음 문제로 넘어가서, 자동 넘김을 없애고 "다음 ▶" 버튼을 눌러야 넘어가게 했습니다. 마지막 문제는 "결과 보기 ▶"로 바뀝니다.
    - **정답인데 틀렸다고 나옴 (○× 퀴즈)**: ×문제에 다른 단어의 뜻을 보여 주는데, 그 뜻이 정답 뜻과 겹치는 경우가 있었습니다. 예를 들어 deduce(추론하다)에 infer의 뜻 "추론하다"가 나오면 사실은 정답입니다. 뜻을 쉼표·공백으로 나눠 겹치면 오답 보기에서 빼도록 했습니다. 피드백에도 "'○○'은 ○○의 뜻이에요"처럼 그 뜻이 어느 단어의 것인지 보여 줍니다.
    - **같은 문제가 전투에도 있었음**: 4지선다 오답 보기가 정답과 뜻이 겹칠 수 있어서 같은 검사를 붙였습니다 (`srs.js`의 `koOverlap`을 전투와 ○× 퀴즈가 함께 씀). 같은 뜻이 보기에 두 번 나오는 것도 막았습니다.
    - **답이 두 개가 되는 미니게임 3곳**:
      - 어근 분류 달리기: transfusion(정답 fus)에 오답 바구니로 trans가 나오면 둘 다 맞습니다. 단어 철자에 들어 있는 어근은 오답 바구니로 내지 않게 했습니다.
      - 어근 단어 사냥: `com / con`처럼 이름에 `/`가 있는 어근은 철자 필터가 작동하지 않아, confuse가 "다른 어근 단어"로 나올 수 있었습니다. `/`로 나눠 각각 검사하게 고쳤습니다.
      - 짝 맞추기: tact(재치)와 tactful(재치 있는)처럼 뜻이 겹치는 단어가 한 판에 같이 나오지 않게 했습니다.

15. **전체 단어 검수** (2026-11-15, 커밋 `dc2648f`): 새 단어뿐 아니라 기존 1,198개도 한 줄씩 다시 봤습니다. 결과는 **어근 167개, 단어 1,417개** (번역 1,417개)입니다.
    - **어원 오류로 뺀 단어 6개**:

      - dose: 라틴어 donare가 아니라 그리스어 dosis에서 와서, condone(묵인하다)으로 바꿨습니다.

    - **확인 방법**: 데이터 검사 스크립트(중복, 번역 개수, 어근당 5~10단어, 예문 형식, 예문에 단어 포함)와, 가짜 화면 위에서 실제 게임 코드를 돌리는 통합 검사(전투 200판, ○× 6,000문제, 분류 달리기·사냥·짝 맞추기)를 모두 통과한 뒤 push했습니다. push 후 사이트에 `words4.js`와 캐시 `v4`가 올라온 것까지 확인했습니다.

## 2. 막혔던 문제와 해결 방법

| 문제 | 원인 | 해결 |
|---|---|---|
| 카톡에서 열면 음성이 안 들림 | 카톡 안의 브라우저는 음성 기능이 막혀 있는 경우가 많음 | 카톡 안에서는 안내를 띄우고 "크롬/사파리로 열기" 링크 제공. 외부 브라우저에서는 정상 |
| 안드로이드에서 영어 음성을 못 찾을 수 있음 | 언어 표기가 `en_US`(밑줄)와 `en-US`(하이픈)로 다름 | 둘 다 찾도록 수정, 음성 목록이 늦게 로드되는 것도 처리 |
| 같은 단어가 두 어근에 들어감 (biography) | 단어를 늘리다 중복 | 점검 스크립트로 중복을 찾아 하나 삭제 |
| 어근과 안 맞는 단어가 섞임 (airport, captain, rural 등) | 철자가 비슷해서 잘못 분류 | 검수에서 찾아 어원에 맞는 단어로 교체 |
| 어색한 영어 예문 | 짧게 쓰다 문법이 어색해짐 | 검수 후 문장 수정 (예: commit to studying) |
| 아이콘이 배경만 나옴 | PowerShell에서 함수 이름 `R`이 기본 명령(별칭)과 겹침 | 함수 이름을 `Box`로 변경 |
| 저장소를 찾을 수 없다는 오류 | GitHub에서 저장소를 아직 안 만들었음 | 사이트에서 빈 공개 저장소를 만든 뒤 push |
| 파일 수정이 한 번 실패함 | 줄바꿈 방식(LF/CRLF) 차이로 찾는 글자가 안 맞음 | 한 줄 단위로 위치를 확인한 뒤 다시 수정 |
| `python`이 실행되지 않음 | 윈도우의 가짜 python 바로가기 | Node.js로 테스트 서버를 만들어 사용 |
| 미니게임 추가 후 "화면이 멈췄다"고 느낌 | 확정하지 못함. 홈 화면은 정상으로 떠 있었고, 자동 플레이 테스트에서도 오류 없음 | `Ctrl+F5` 강력 새로고침 후 정상 (이전 파일이 브라우저에 남아 있었을 가능성). 다시 생기면 `F12` → Console의 빨간 글씨를 확인 |
| 헤드리스 Chrome 테스트가 "파일 없음"으로 실패 | Git Bash 경로(`/c/...`)를 그대로 `file:///`에 넣음 | `C:/Users/...` 형태의 윈도우 경로로 바꿔서 실행 |
| 작업용 `.txt`(대화 기록)가 공개 저장소에 올라갈 뻔함 | `git add -A`는 새 파일을 전부 담음 | `git add`에 올릴 파일만 지정하고, 배포 규칙(`CLAUDE.md`)에도 반영 |
| ○× 퀴즈에서 "정답인데 틀렸다고 나옴" | 오답으로 보여 준 다른 단어의 뜻이 정답 뜻과 겹침 (예: deduce ↔ infer "추론하다") | 뜻이 겹치는 후보는 오답에서 제외. 처음엔 판정 코드만 의심했는데, 코드는 맞고 데이터(뜻 겹침)가 원인이었음 |
| 고친 뒤에도 "아직 틀린다"는 말을 들음 | 고친 내용을 push하지 않아, 인터넷 주소에서는 옛 버전이 돌아가고 있었을 가능성 | 어디서(내 컴퓨터 / 인터넷 주소) 확인했는지 먼저 묻기. 피드백에 "그 뜻이 어느 단어의 것인지" 보여 줘서 원인을 바로 알 수 있게 함 |
| 검사 스크립트가 "모두 통과"라고 했는데 물음표 예문 17개를 못 잡음 | 검사 코드를 백틱(템플릿 문자열) 안에 넣어서 `\.`의 역슬래시가 사라짐 → 아무 문자로나 끝나면 통과 | 검사 코드는 템플릿 밖의 별도 파일로 작성. **검사기가 실제로 오류를 잡는지, 고치기 전에 먼저 확인** |
| 생성 스크립트로 만든 `trans.js`가 git에서 파일 전체가 바뀐 것으로 보임 | 원래 CRLF 줄바꿈인 파일 뒤에 LF로 이어 붙여 섞임 | CRLF로 통일한 뒤 다시 확인 (변경이 추가한 줄만 보이게 됨) |
| 테스트에서 "오답인데 체력이 그대로"가 대량 발생 | 게임이 아니라 테스트 루프 문제: 전투가 끝난 뒤에도 버튼을 눌렀는데 잠금 상태라 무시됨 (정상 동작) | 테스트의 종료 조건을 고침. 실패가 쏟아지면 한 판을 직접 따라가 원인부터 확인 |
| 단어를 빼면 학생 폰의 기록과 안 맞음 | 기록은 단어 철자로 저장돼 있어 빠진 단어도 남음 | 익힌 단어 수·취약 단어 목록은 지금 데이터에 있는 단어만 세도록 수정 |

- [ ] 한 단계 끝날 때마다 브라우저에서 직접 눌러 본다
- [ ] 파일을 고칠 때마다 `node --check`로 문법 확인
- [ ] 화면이 있는 기능은 헤드리스 Chrome(`--headless=new --virtual-time-budget=... --dump-dom`)으로 자동 플레이해 오류와 멈춤을 확인한다. 저장 기록이 있는 상태에서도 한 번 돌려 본다
- [ ] 새 기능을 배포하면 `sw.js`의 `CACHE` 숫자를 올린다
- [ ] 데이터는 중복, 개수, 빠진 항목을 스크립트로 점검한다
- [ ] AI가 만든 내용(뜻, 예문, 번역)은 사람이 한 번 검수한다
- [ ] 단어를 넣을 때는 어원을 확인한다. 철자가 비슷해도 어원이 다른 단어(isolate, miniature, adjust 등)가 많다
- [ ] 난이도 기준(예: 중고등 교과서·수능 범위)을 먼저 정하고 단어를 고른다
- [ ] 객관식·○× 문제는 "오답 보기가 사실 정답일 수 있는지" 확인한다 (뜻이 겹치는 단어, 철자에 두 어근이 다 들어 있는 단어)
- [ ] 점검 스크립트는 일부러 틀린 데이터를 넣어 실제로 잡는지 먼저 확인한다
- [ ] 단어를 빼거나 바꾸면, 이미 저장된 사용자 기록이 화면에서 어떻게 보이는지 확인한다

**휴대폰·공유**
- [ ] 카톡으로 링크를 보낼 때는 카톡 안 브라우저에서 음성·설치가 안 될 수 있음을 안내한다
- [ ] 실제 폰에서 소리, 화면 크기, 터치를 확인한다
- [ ] 설치형 앱(PWA)에는 아이콘, manifest, `sw.js`가 필요하다. 새 파일을 만들면 `sw.js`의 `FILES`에 추가한다

**올리기 전**
- [ ] 파일에 API 키, 비밀번호, 개인 이메일이 없는지 확인한다
- [ ] 공개 저장소의 커밋에는 GitHub noreply 이메일을 쓴다
- [ ] push 전에 올릴 내용을 한 번 더 확인한다 (`git status`로 작업용 파일이 섞이지 않았는지 보고, 파일을 하나씩 지정해 `git add`)
- [ ] push 후 1~2분 뒤 실제 주소에서 열리는지 확인한다
