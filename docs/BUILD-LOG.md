# 만든 과정 기록 (BUILD-LOG)

영어 어근 단어 암기 웹 게임 "어근 디펜스"를 처음부터 배포까지 만든 과정입니다.
코딩을 잘 몰라도 다시 따라 할 수 있게 쉬운 말로 적었습니다.

## 1. 단계별 진행 순서

1. **계획 세우기**: 붙여 둔 아이디어(디펜스, 육성, 모험, 미니게임, 경쟁)가 너무 커서, 첫 버전은 **디펜스 + 육성**만 만들기로 정했습니다. 나머지는 나중으로 미뤘습니다.
2. **큰 결정 4가지**: 웹앱으로 만들기 / 기록은 기기 안에만 저장 / 단어는 AI가 만들고 사람이 검수 / 배포는 GitHub.
3. **첫 버전 만들기**: 어근 29개, 단어 118개로 학습 카드, 전투(10문제), 레벨·코인·연속 학습, 성장 기록을 만들었습니다.
4. **직접 실행해 보기**: `index.html`을 더블클릭해서 브라우저에서 확인했습니다.
5. **기능 추가**: 음성(단어·예문 읽어 주기), 전투 중간에 그만두기, 어근당 단어 5~10개로 늘리기.
6. **단어 대량 추가**: 어근 101개, 단어 635개까지 늘렸습니다.
7. **검사**: 문법 검사(`node --check`), 중복·개수 점검 스크립트, 영어 예문과 뜻을 다른 눈으로 다시 검수했습니다.
8. **예문 한글 번역 추가**: `data/trans.js`에 635개 번역을 넣었습니다.
9. **GitHub에 올리기**: 저장소 `root-word-game`을 공개로 만들고 `git push`, 그다음 Pages를 켰습니다.
10. **카톡 공유 문제 해결**: 카톡 안에서 열면 음성이 안 나와서 안내 배너를 넣었습니다.
11. **홈 화면 설치(PWA)**: 갤럭시에서 앱처럼 설치할 수 있게 아이콘, 설치 안내, 오프라인 저장을 추가했습니다.

## 2. 막혔던 문제와 해결 방법

| 문제 | 원인 | 해결 |
|---|---|---|
| 카톡에서 열면 음성이 안 들림 | 카톡 안의 브라우저는 음성 기능이 막혀 있는 경우가 많음 | 카톡 안에서는 안내를 띄우고 "크롬/사파리로 열기" 링크 제공. 외부 브라우저에서는 정상 |
| 안드로이드에서 영어 음성을 못 찾을 수 있음 | 언어 표기가 `en_US`(밑줄)와 `en-US`(하이픈)로 다름 | 둘 다 찾도록 수정, 음성 목록이 늦게 로드되는 것도 처리 |
| 같은 단어가 두 어근에 들어감 (biography) | 단어를 늘리다 중복 | 점검 스크립트로 중복을 찾아 하나 삭제 |
| 어근과 안 맞는 단어가 섞임 (airport, captain, rural 등) | 철자가 비슷해서 잘못 분류 | 검수에서 찾아 어원에 맞는 단어로 교체 |
| 어색한 영어 예문 | 짧게 쓰다 문법이 어색해짐 | 검수 후 문장 수정 (예: commit to studying) |
| 아이콘이 배경만 나옴 | PowerShell에서 함수 이름 `R`이 기본 명령(별칭)과 겹침 | 함수 이름을 `Box`로 변경 |
| 저장소를 찾을 수 없다는 오류 | GitHub에서 저장소를 아직 안 만들었음 | 사이트에서 빈 공개 저장소를 만든 뒤 push |
| 파일 수정이 한 번 실패함 | 줄바꿈 방식(LF/CRLF) 차이로 찾는 글자가 안 맞음 | 한 줄 단위로 위치를 확인한 뒤 다시 수정 |
| `python`이 실행되지 않음 | 윈도우의 가짜 python 바로가기 | Node.js로 테스트 서버를 만들어 사용 |

**업로드과정(내용추가)**
1. GitHub에서 빈 저장소를 만들어 주세요. (AI가 만들수 없음)
2. github.com에 로그인한 뒤 오른쪽 위 + → New repository를 누르세요.
3. 이름은 root-word-game, 공개 설정은 Public으로 하세요.
4. README나 .gitignore 추가 옵션은 모두 체크하지 마세요. 빈 저장소여야 합니다.
5. Create repository를 누르세요.

6. 이후 GitHub 아이디를 알려주고, AI가 커밋하고 main 브랜치로 업로드(Push) 처음에는 GitHub 로그인 창이 뜰 수 있음
7.  Settings → Pages에서 main 브랜치를 선택하는 방법을 안내해 드립니다. 이 설정은 GitHub 웹에서 직접 해야함.
8.  1~2분 뒤 링크가 열리는지 확인하고, 카톡으로 보낼 안내 문구를 만들어 줌
9.  업로드가 끝났습니다. 파일이 skyou-sp/root-word-game의 main 브랜치에 올라갔습니다. 이제 링크가 열리도록 Pages를 켜야 합니다.

GitHub Pages 켜기 (웹에서 직접 해야함)
1. https://github.com/skyou-sp/root-word-game 로 가서 위쪽 Settings 탭을 누르세요.
2. 왼쪽 메뉴에서 Pages를 누르세요.
3. Build and deployment의 Source를 Deploy from a branch로 두세요.
4. Branch를 main, 폴더를 / (root)로 고르고 Save를 누르세요.
5. 1~2분 기다리면 Pages 화면 위쪽에 "Your site is live at …" 주소가 나옵니다.
6. 이후 앱주소를 복사한 후 열어서 앱이 뜨는지 확인.

## 3. 다음에 비슷한 앱을 만들 때 체크리스트

**시작 전**
- [ ] 한 번에 다 만들지 말고 핵심 기능 하나로 시작한다
- [ ] 어디서 쓸지(폰/PC), 기록을 어디에 저장할지 먼저 정한다
- [ ] GitHub 계정이 있는지, 컴퓨터에 git이 설치돼 있는지 확인한다

**만드는 중**
- [ ] 데이터(단어 등)는 코드와 분리된 파일에 둔다
- [ ] 한 단계 끝날 때마다 브라우저에서 직접 눌러 본다
- [ ] 파일을 고칠 때마다 `node --check`로 문법 확인
- [ ] 데이터는 중복, 개수, 빠진 항목을 스크립트로 점검한다
- [ ] AI가 만든 내용(뜻, 예문, 번역)은 사람이 한 번 검수한다

**휴대폰·공유**
- [ ] 카톡으로 링크를 보낼 때는 카톡 안 브라우저에서 음성·설치가 안 될 수 있음을 안내한다
- [ ] 실제 폰에서 소리, 화면 크기, 터치를 확인한다
- [ ] 설치형 앱(PWA)에는 아이콘, manifest, `sw.js`가 필요하다. 새 파일을 만들면 `sw.js`의 `FILES`에 추가한다

**올리기 전**
- [ ] 파일에 API 키, 비밀번호, 개인 이메일이 없는지 확인한다
- [ ] 공개 저장소의 커밋에는 GitHub noreply 이메일을 쓴다
- [ ] push 전에 올릴 내용을 한 번 더 확인한다
- [ ] push 후 1~2분 뒤 실제 주소에서 열리는지 확인한다
